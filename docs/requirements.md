# 重构需求与验收契约

本项目针对多渠道模型 API 的延迟、流输出、推理、缓存和成本测量。需求来自实际使用问题；历史厂商结果不作为当前产品能力或性能的证明。

## 来源与范围

上游为 [saksham10arora-dotcom/llm-bench](https://github.com/saksham10arora-dotcom/llm-bench)，核验基线为 `4ed36ae9ee2c3d4b78450ce7c9b720f881d40f4e`，包版本为 `llm-latency-bench 0.3.0`。保留原 MIT 许可证。当前仓库独立发布，避免与旧 PyPI 包混淆。

离线复现确认：reasoning-only 被判为无内容；增加 100 个推理 token 会把相同正文窗口的计算速度从 9 抬高到 109 tok/s；单个内容块的输出被记为 0 tok/s；比较模式的 JSON 缺少第二组样本。上游已正确等待预热结束再开始正式请求，但预热失败与结果未归档。

## 核心契约

| 编号 | 需求 | 验收依据 |
| --- | --- | --- |
| R01 | 按渠道配置 URL、模型 ID、环境变量名、协议、路径和参数 | 同一轮混合多个 Chat、Responses 渠道，禁止直接配置密钥 |
| R02 | 解析正文、推理、推理摘要、工具调用和结束状态 | reasoning-only 保留时间与用量；摘要不能充当原始推理 token 流 |
| R03 | 思考模式 default / on / off，可按渠道覆盖 | off 请求用渠道对应字段；收到推理则失败；缺少零推理用量证据则不能宣称通过 |
| R04 | 原始网络与流事件时间线 | DNS、TCP、TLS、响应首字节、响应头、第一条 SSE、首末正文和推理、流结束可追溯 |
| R05 | 复用连接与每次新连接独立控制 | 本地真实 HTTP/TLS 服务器验证 reuse 标识和握手事件 |
| R06 | 串行或同轮并发，保留每个渠道的样本 | 记录轮次起点、实际请求起点和并发上限；所有渠道进入 JSON |
| R07 | 前缀缓存独立实验 | 隔离前缀的冷候选 → 同协议热样本 → 其他协议探测；逐请求记录缓存与未命中 token |
| R08 | 预热使用独立前缀且归档 | 不污染正式前缀，不把预热纳入正式摘要；预热不保证厂商模型已热或正式连接一定复用 |
| R09 | 不伪造缺失或不可观测指标 | 缺少 usage 保留 null；禁止 split() 估中文 token；单块 decode 速度为 null |
| R10 | 定价由渠道显式配置并注明来源日期 | 分币种报告，缓存折扣可配置；缺少价格或关键计费 token 时成本为 null |
| R11 | 明确错误与限制 | HTTP 状态、request ID、结束原因、错误类型和脱敏摘要可归档；截断流不能算成功 |
| R12 | 真正发送多轮及多模态内容 | Chat 消息转换为 Responses 输入；图片、文件等不支持的映射明确报错 |
| R13 | 可重建的统一报告 | JSON 包含完整样本、配置、时间线、用量和摘要；终端从同一 Report 生成 |
| R14 | 轻量、快速、可分发 | 单文件 CLI；本地离线测试；CI 运行 race / vet / 构建并上传制品 |

## 测量口径

所有请求内时间使用单调时钟的毫秒偏移，跨请求关联使用 UTC 墙上时钟。DNS、TCP、TLS 是客户端观察到的路径阶段；连接建立后的等待仍包含网络、网关、排队与预填充，不能直接称为服务端排队时间。连接复用时不存在本次握手样本，显示缺失而非零。

正文首响应和推理首响应分别记录。摘要流有自己的时间线。只有能把 token 数映射到观察窗口时，才给出解码速度；分块中可能包含多个 token。没有首块 token 数时，用总 token 减一的公式只能作为明确标注的近似值，不是逐 token 测量。推理总用量不能直接除以推理摘要持续时间。

短输出仍报告完整请求时间、正文首响应和输出 token / 请求总时间；无可观察解码区间不填 0。单路 tok/min 是对应 tok/s × 60，不能解释为账号 TPM；账号 TPM 仅从明确配置的配额响应头读取。

少于 100 个有效延迟样本时，尾部显示最大值，标签为「最慢一次 / max」。达到 100 个有效样本后才显示 p99，仍属于经验分位数，不代表已证明的长期尾部 SLA。失败、截断、思考检查失败的样本必须计入失败率或独立状态统计，不能静默消失。

## 缓存实验限制

客户端不能强制清空厂商缓存。「冷候选」表示在输入起始位置注入每组唯一前缀；是否冷以返回缓存用量判断。系统模板或不可见服务端前缀仍可能命中。缓存块大小是渠道配置，不能硬编码成所有厂商都使用 128。命中比例小于 1 不自动表示故障：尾部、协议包装、隐式系统提示、缓存策略都可能影响 token 计数。

跨协议复用仅能观察同渠道配置序列的缓存字段，不能仅凭命中就证明缓存共享；系统可能已经有相同隐藏前缀。实验报告必须保留方向、先后关系、请求内容指纹和每个协议的输入 token 数。

## 不在本次范围

不实现厂商服务端的内部排队探针，不猜测账号配额，不维护没有已核验来源的价格常量，不把少量冒烟请求宣传成四家性能结论。不将文本负载的延迟基准称为模型质量、准确率或安全评测；质量评测需要独立数据集与评分器。
